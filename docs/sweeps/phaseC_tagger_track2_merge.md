Default = **lead**: the latest non-empty extractor answer is a whole-conversation judgment, so it leads the
final guesses in its own order. Keyphrase-idf only fills empty slots (or all slots before the first non-empty
answer; tomas `bh_yoked_d2 s11` had an empty turn-6 reply), and keyphrase duplicates of a ranked label are dropped.
There is no tuned constant; the soft prior (one constant) is shown for contrast. On these sessions lead equals "direct" by
construction (the last call is at the final turn): the merge no longer loses anything, and the ceiling is now
the extractor's own answer. Interest-map evidence/ledger is unchanged (14/24 holds).

**Top-1 diagnosis (old merge, extractor alone, 2/24 vs direct 9/24).** Where did its top-1 come from?
- 12/24: a lower-ranked label of the SAME turn-12 answer (rank 2: 7, rank 3: 2, rank 4: 3).
- 8/24: the extractor's rank-1 label, same as direct.
- 2/24: a turn-6-only label that persisted 6 snapshots.
- 2/24: a Director broad topic ("music", "sports").

All labels of one answer are observed on the same turn with the same engagement value, so the extractor's order
was thrown away. What remained:
- `observeWeight = 0.7 x confidence x min(3, cited turns)`: multi-turn mentions beat the extractor's pick.
- persistence, which favours earlier (turn-6) labels and broad topics the Director probed.

Fix (implemented): use the answer's rank order (lead). Top-1 then matches direct (9/24). Beyond that, top-1 is
limited by the extractor's own first pick. Next step (proposed, not built): put the per-turn engagement in the
extractor prompt, or re-rank the answer's labels by the engagement of the turns they cite, as a tie-break
only. That should be validated on a fresh session set, not on these 24.

The keyphrase-idf row here (3/24) uses the bundled CC0 table; the earlier `phaseC_tagger_track2.md` (4/24) used wordfreq.
144-session regression check after this change: keyphrase-only / keyphrase-idf (CC0) / keyphrase-idf (wordfreq) final
labels identical to `phaseC_tagger_idf_cc0_vs_wordfreq.jsonl` in 144/144 sessions each (3/144, 21/144, 23/144 top-3).
Leak checks: both PASS (`phaseC_tagger_track2_merge_leak_check.txt`).
